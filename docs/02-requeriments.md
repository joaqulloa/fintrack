FinTrack — Requirements

1. Functional Requirements

FR-01: Create Transaction

The system must allow users to register income and expense transactions.

Each transaction must include a description, amount, type, date, and category.

FR-02: View Transactions

The system must display a list of registered transactions, including their descriptions, amounts, dates, types, and categories.

FR-03: Update Transaction

The system must allow users to modify an existing transaction.

FR-04: Delete Transaction

The system must allow users to delete a transaction after confirming the action.

FR-05: Validate Transactions

The system must reject transactions with invalid amounts, missing required fields, or incompatible categories.

Amounts must be greater than zero.

FR-06: Categorize Transactions

Transactions must be associated with a category compatible with their type.

Examples include salary and freelance income for income transactions, and food, transportation, housing, and entertainment for expenses.

FR-07: Filter Transactions

Users must be able to filter transactions by date range, transaction type, and category.

FR-08: Financial Summary

The dashboard must display total income, total expenses, and net balance for the selected period.

Net balance is calculated as total income minus total expenses.

FR-09: Spending Breakdown

The dashboard must display an expense breakdown by category.

FR-10: Monthly Trends

The system should display income and expense trends over time.

2. Business Rules

* Transaction amounts must be positive decimal values.
* Every transaction must have a valid category.
* Income categories can only be associated with income transactions.
* Expense categories can only be associated with expense transactions.
* The financial balance is calculated from transaction records and must not be stored as an independently editable value.
* Financial summaries must respect the selected date range.
* The initial application currency is CLP.
* Calculations must avoid floating-point precision errors.

3. Non-Functional Requirements

NFR-01: Usability

The interface must be intuitive and responsive across desktop and mobile devices.

NFR-02: Maintainability

Frontend, backend, and database responsibilities must be separated clearly.

NFR-03: Reliability

The system must validate incoming data and return consistent API responses.

NFR-04: Testing

Core business rules and API endpoints must have automated tests.

NFR-05: Security

The backend must validate all incoming requests. Database credentials and other secrets must be stored outside the source code.

NFR-06: Performance

Database queries and API endpoints should remain responsive for typical personal finance usage.

NFR-07: Documentation

The project must include setup instructions, API documentation, and a description of its architecture.

4. Out of Scope

The initial release will not include:

* Direct bank account integrations.
* Automatic bank transaction imports.
* Investment portfolio management.
* Tax filing or accounting compliance.
* Payment processing.
* Financial advice generated by artificial intelligence.
